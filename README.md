# Pro Timer

A speedcubing timer for competition-style practice, without setup or bookkeeping by hand.

Its average system started as a bug: averages of 5 came out in fixed blocks of five solves instead of rolling over the last five. That turned out to feel like a competition round, so it became the timer's main idea.

**Try it:** https://cubing-way.github.io/Pro-timer/

## Features

- **Events and scrambles:** every WCA event plus csTimer's training sets (PLL, OLL, ZBLL, COLL, last layer, edges or corners only…), generated by csTimer's scrambler in a worker, with a picture of the scrambled cube drawn by [cubisz](https://github.com/Cubing-Way/cubisz). Previous and Next in the top bar go back through the scrambles you've seen or skip to a new one, in every event.
- **Block averages:** ao5, mo3, bo3, bo5 and ao3 (for FMC) are counted in blocks, like competition rounds. *Classic* keeps the usual rolling averages.
- **Sessions:** separate sessions with their solve history, +2 and DNF penalties, and the details of every solve and average, including the one in progress. In the details, each solve is one line (its time, with an ao5's dropped best and worst in parentheses, and the start of its scramble) that opens to its penalty buttons and details. The session select's "▲ Move current up" and "▼ Move current down" options move the session in use up or down the list, and the order is saved.
- **Done at:** every solve remembers where it was done: the name you give this device in Settings → Data (or, without one, its model, like "Pixel 8" or "iPhone", its system on a computer, like "Windows PC" or "Mac", or else Cellphone or Tablet), the competition for WCA results, or the app for solves imported from other timers. The solve details show it.
- **With:** solves timed or typed in the app also remember how the time was entered, Timer or Typing. The solve details show it.
- **Statistics:** per session, over all time, the year, the semester, the month, the week or the day. The page opens on the smallest of those periods that has solves (today if you solved today), so it never opens empty.
- **Timer:** WCA inspection and delay flag, timer phases, typed-in times, hide the time while solving, and timer warnings for long attempts (such as a 1-hour limit).
- **Fewest Moves:** write your solution, test it on the cube and submit it; cubisz checks it and counts the moves.
- **Multi-Blind:** pick how many cubes and get a scramble for each.
- **TPS:** turns per second for a solve once its move count is known.
- **Sharing:** every average and every solve in the session details has a Share button. It makes a text with the event, the average and its best, worst and σ, then each solve with everything the details show (scramble, inspection, date, done at, with, solution), with dropped times in parentheses like csTimer. On a phone or tablet it opens the share sheet (WhatsApp, Discord…); on a computer it copies the text.
- **Look:** colors for the text, backgrounds and buttons, and switches for the scramble picture, statistics, session history, scramble text, penalty bar and average preview.
- **Saving:** sessions and settings stay in your browser.
- **Import / export:** Settings → Data downloads every session as one backup file, and loads solves from a Pro Timer backup, csTimer ("Export to file" or a session's CSV), CubeDesk, Twisty Timer, a plain list of times, or a competition's WCIF file (the JSON WCA Live and the WCA website use), where you pick whose results to import and every round lands dated by the competition's schedule. After you pick a file, a pop-up asks which of its sessions to import (all of them or just one) and where: as new sessions, or into the session in use, where the solves are grouped into its averages by date without repeating solves it already has. **WCA sync** remembers a WCA ID and keeps that competitor's official results from the WCA website in one session per event ("WCA 3x3x3"…), where every round with a full average (ao5, mo3, bo3, bo5) is its own average, matching the official one. **Sync** fetches the results again and opens the same import pop-up as files: all events or one, into their WCA sessions (only the solves they don't have yet, creating missing sessions) or into the session in use. The app also syncs on its own once a day when it opens online, with no pop-up, updating only the WCA sessions you already have. Importing and syncing never replace or delete anything.
- **Offline:** after the first visit, the app works without internet. When a new version is out, a bar asks before switching to it, so it never reloads in the middle of a solve.

## Run it

```bash
npm install
npm run dev
```

Then open http://localhost:3000/Pro-timer/.

## Build and deploy

```bash
npm run build
```

The site lands in `dist/`. `npm run deploy` builds it and publishes `dist/` to the `gh-pages` branch, which GitHub Pages serves.

## Test offline

The service worker only exists in the build (`npm run dev` doesn't register one), so test offline mode on a built copy:

```bash
npm run preview
```

It builds, then serves `dist/` at http://localhost:4173/Pro-timer/. Open it once, then in DevTools tick **Offline** in the Network tab (or stop the server) and reload. DevTools → Application → Service workers and Cache storage show what's registered and cached. To start over, click **Unregister** there and delete the `workbox-precache-…` cache.

## Folder layout

- `index.html`: the page skeleton; each part of the page lives in its own folder
- `vite.config.js`: Vite settings, the plugin that puts the page's HTML pieces together, and the offline plugin
- `main/`: entry point, the bridge to csTimer's scrambler, page-wide styles
- `timer/`: the timer, inspection, WCA delay, phases, countdown and time formatting
- `average/`: block and classic averages
- `session/`: sessions and solves
- `scramble/`: scramble types, generation and the scramble picture
- `cubisz/`: the cubisz cube, used for scramble pictures and Fewest Moves checks (a copy of its own repo, with a demo page and its own `style.css`)
- `event/`: Fewest Moves, Multi-Blind and the timer warnings
- `render/`: history list, statistics and average views
- `stats/`: the statistics page and its charts
- `settings/`, `topbar/`, `modal/`, `timeTyping/`: settings, top bar, pop-ups and typed-in times
- `importExport/`: the backup file, reading other timers' files (Pro Timer, csTimer, CubeDesk, Twisty Timer, lists of times) and competition files (WCIF) into sessions, and fetching WCA results
- `offline/`: registers the service worker that makes the app work offline, and the bar that offers new versions
- `public/`: files served as they are: csTimer's scrambler worker (`cstimer_module.js`) and the timer warning sounds (`audio/`)

Each folder has a `…Controller.js`. It holds the folder's state and page wiring (listeners, startup code), and it is what other folders import. The other files only export functions: when one needs state, its controller passes it in. State shared between folders lives in `…State.js` files (`avgState.js`, `sessionState.js`, `settingsState.js`, `timerState.js`, `topbarState.js`). `main/mainController.js` loads the controllers, then shows the first scramble.

A folder also holds the HTML and CSS of the part of the page its controller wires up, so the markup, the styles and the code for one feature sit side by side.

## The page (HTML)

`index.html` is only a skeleton. Each part of the page is in its own `.html` file, and the skeleton pulls it in with a tag like this:

```html
<include src="./topbar/topbar.html"></include>
```

`<include>` is not real HTML. The `htmlIncludes` plugin in `vite.config.js` replaces every `<include>` tag with the contents of that file before the browser sees the page, both in `npm run dev` and in `npm run build`, so the browser only ever gets one complete page, the same as if it were written in one file. How it works:

- `expandIncludes(html, fromDir)` finds each `<include src="…"></include>` with a regular expression (`INCLUDE_TAG`), reads that file and puts its contents in place of the tag.
- It runs again on the file it just read, so a piece can include smaller pieces. The path in `src` is relative to the file that has the tag, like an `import`.
- The plugin's `transformIndexHtml` hook runs it on `index.html` with `order: "pre"`, before Vite's own HTML handling, so Vite still processes the `<link>` and `<script>` tags as usual.
- Vite doesn't track the pieces as modules, so its `handleHotUpdate` hook reloads the page whenever any `.html` file changes in dev.

Because the whole page is there before any script runs, the controllers can still look up their elements with `document.getElementById` when they load.

## Styles (CSS)

`index.html` links a single stylesheet, `main/style.css`. That file has no rules of its own: it `@import`s every other stylesheet, and Vite inlines them into one file (in dev and in the build). The import order matters, because when two rules match the same element equally strongly, the one imported later wins. Each phone rule sits at the end of its own file in a `@media (max-width: 768px)` block, after the desktop rules it overrides.

How the colors work: every color in the stylesheets is a CSS variable (`--bg-main`, `--bg-secondary`, `--bg-tertiary`, `--text-main`, `--text-strong`, `--border-main`, `--accent`…), with defaults in `main/variables.css`. The theme classes are tables of values for those variables. Each color setting changes one variable:

| --- | --- | --- |
| Main text | `--times-color` | Times and numbers |
| Secondary text | `--text-main` (via a class on `<body>`) | All other text |
| Main background | `--bg-main` | Page, right sidebar, penalty bar, footer, stats page, settings panel |
| Secondary background | `--bg-tertiary` | Top bar, left sidebar, settings rows |
| Tertiary background | `--bg-secondary` | Pop-ups, stats table header |
| Buttons background | `--border-main` | Buttons, selects, inputs and most borders |

Some elements are hidden in the CSS and shown by the code: the event buttons and Fewest Moves panel (`event/eventLayout.js`, `event/FMC.js`, `event/MBLD.js` set their `display`), and the pop-ups (opened by adding `.open`, removing `.hidden`, or setting `display`). The Layout settings hide parts of the page by class (`settings/layout.js`). The difference beside the timer (`#time-diff`) is hidden by both: the "Time difference" switch sets its `display`, and Fewest Moves and Multi-Blind set its `hidden` attribute instead (`showTimerLayout` clears it), so neither undoes the other. `hidden` only works because no stylesheet gives `#time-diff` a `display`.

## Build config (`vite.config.js`)

- `base: "/Pro-timer/"`: the site is served from `cubing-way.github.io/Pro-timer/`, so every URL starts with `/Pro-timer/`.
- `server.port: 3000`: the dev server address.
- `worker.format: "es"`: web workers are built as ES modules.
- `build.minify: false`: the built code stays readable.
- `plugins`:
  - `htmlIncludes()`: puts the HTML pieces together (see [The page](#the-page-html)).
  - `VitePWA({...})` from [vite-plugin-pwa](https://vite-pwa-org.netlify.app/): writes the service worker (`dist/sw.js`, plus the Workbox library it uses) at build time (see [Offline](#offline)). Its options:
    - `registerType: "prompt"`: a new version waits until the user clicks Reload, instead of reloading the page on its own.
    - `injectRegister: false`: the plugin adds no registration script; `offline/offlineController.js` registers the service worker.
    - `manifest: false`: no web app manifest yet (it needs app icons), so the app works offline but can't be installed.
    - `workbox.globPatterns`: which files in `dist/` go in the precache list: `js`, `css`, `html` and `mp3`.
    - `workbox.ignoreURLParametersMatching`: `main/cstimer.js` loads the scrambler as `cstimer_module.js?worker_file&type=classic`; ignoring `worker_file` and `type` lets that request find the cached `cstimer_module.js`.

## Code

Plain JavaScript modules, no framework. Each folder's controller runs its setup code (listeners, saved settings, first draw) the first time it's imported. Folders share state through the `…State.js` objects, and functions that need state get it passed in by their controller.

### Startup

1. `index.html` links `main/style.css`, then loads `main/mainController.js` as a module.
2. `mainController.js` imports every controller. A module's code runs once, after the modules it imports, so things happen in dependency order:
   - `session/sessionState.js` reads all sessions from localStorage, and `session/sessionController.js` loads the current one's average in progress (`changedSession`) and fills the session select.
   - `settings/settingsController.js` applies the saved colors, layout switches and timer settings, and fills `deviceSettObj.detected` with the device's type right away (its model replaces it a moment later, when the browser gives one).
   - `event/eventController.js` picks where scramble pictures go (`vis`: the desktop corner, or the phone pop-up when the window is 768px wide or less) and shows the timer or the typing box.
   - `topbar/topbarController.js` fills the category select, sets the category, event and mode selects to the session's (running their change handlers), wires the penalty buttons and draws the history (`renderHistory`).
   - `importExport/importExportController.js` wires the Data section's Export, Import and WCA Sync buttons, puts the saved WCA ID in its box and "Last synced …" under it, and starts the daily WCA sync (`syncWca(true)`: no pop-up, only the WCA sessions that already exist) when there's a saved ID, the browser is online and the last sync is over a day old. The sync isn't awaited, so the app keeps loading while the results download.
   - `offline/offlineController.js` registers the service worker (in the build only) and asks the browser to keep the saved data.
3. `mainController.js` calls `showLastSolve()` (`timer/`), so the timer shows the session's last solve instead of the "0.00" in the HTML (Fewest Moves and Multi-Blind keep their countdown).
4. Last, it awaits `initEvent()`, which shows the first scramble and, for Fewest Moves or Multi-Blind, their layout.

### The path of one solve

1. **Press** (space down, or a finger on `#touchOverlay`): `onPressStart` in `timer/timerController.js`. From idle it starts inspection (or waits for the release, with "Press end"); during inspection it starts the hold.
2. **Hold**: `beginHold` (`timer/timerPhases.js`) turns the timer red, and green after 0.3 s (right away with the delay flag off).
3. **Release** while green: `onPressEnd` starts the timer (`startTimer`, `timer/timer.js`) and hides everything but the timer (`showOnlyTimerSafe`).
4. **Press while running** (any key but Tab): `handleSplitOrStop` ends the current timer phase. On the last phase it stops the timer, which shows the time with the "Timer decimals" setting (1, 2 or 3), and formats the time to save itself with `formatTime(totalElapsed)`: always 2 decimals, truncated like the WCA does, whatever the timer shows. Both come from the same `totalElapsed` (ms at the press), so the timer and the history never disagree.
5. `averageOfN` (`average/avgController.js`) works out the inspection penalty and adds the solve to `averageObj.solvesArray`, with its `doneAt` (the device's name or what was detected, from `deviceSettObj`) and its `doneWith` ("Timer" here, "Typing" from the typed-time box). In classic mode it updates the rolling averages; otherwise, once there are enough solves for the mode, it returns a finished average block.
6. `addAverageBlock` (`session/`) puts the block at the start of `session.averages`, and `saveSessions` writes everything to localStorage.
7. `renderHistory` (`render/renderController.js`) redraws the footer, the history list, both stats panels and the difference beside the timer.
8. `displayScramble` (`scramble/scrambleController.js`) asks csTimer's worker for the next scramble and its picture and adds it at the end of the scramble history (so a solve done on an older scramble, after Previous, still gets a new one), and `restoreUI` shows the page again.

Typed-in times (`timeTyping/`), Fewest Moves and Multi-Blind (`event/eventController.js`) skip the timer and call `averageOfN` from step 5 with the typed time, the move count or the points.

### Data

A **solve**, as saved in `averageObj.solvesArray` and in average blocks:

| Field | Meaning |
| --- | --- |
| `time` | Seconds; the move count for Fewest Moves, the points for Multi-Blind |
| `penalty` | `null`, a number of seconds added (2, 4 … 12), or `"DNF"` |
| `result` | Multi-Blind only: `"4 / 5"` |
| `scramble`, `event` | The scramble and the event code it was made for |
| `inspection` | Seconds of inspection used (0 for typed times, FMC, Multi-Blind and solves imported from other apps or the WCA) |
| `createdAt` | When it was saved (ms since 1970), used by the date filters and to find the most recent solve |
| `solution` | Fewest Moves solution, or one typed in the details pop-up |
| `solvePhases` | Time of each timer phase |
| `doneAt` | Where it was done. Solves timed or typed in the app (FMC and Multi-Blind too) get the name typed in Settings → Data → "This device", else the device's model ("Pixel 8", "iPhone", "iPad"), else its type ("Windows PC", "Mac", "Chromebook" or "Linux PC" for a computer, "Computer" when its system is none of those, "Cellphone", "Tablet"); solves saved before computers showed their system say "Computer". It's saved with the solve, so renaming the device later doesn't change older solves. Imported solves get the competition's short name for WCA results and competition files ("Ligeirim Open 2026"), and the app's name for other apps' files ("csTimer", "CubeDesk", "Twisty Timer"); Pro Timer backups keep what their solves have. Lists of times and solves saved before this field existed don't have it, and nothing needs it to be there |
| `doneWith` | How the time was entered: `"Timer"` (a timed solve, given by `handleSplitOrStop`) or `"Typing"` (a typed time, given by `timeTypingController.js`). Fewest Moves and Multi-Blind solves don't have it, since they have no Timer/Typing choice, nor do imported solves (other apps don't say it) or solves saved before it existed; Pro Timer backups keep it. The details pop-up shows it as "With: …" |
| `moves`, `tps`, `status` | Set when a solution is checked in the details pop-up |

An **average block** (one finished average): `mode`, `average`, `best`, `worst`, `sigma` (already formatted as text, like `"12.34"` or `"DNF"`) and `solves`.

A **session** (in `sessionsObj.sessions`, by name): `averages` (finished blocks, newest first), `buffer` (the average in progress: `mode`, `solveCounter`, `solvesArray`), `classicStats` (classic mode's rolling averages), and the `category`, `scrambleType` (event) and `mode` it was last used with. Sessions WCA sync fills also have `wcaSync`: `{ wcaId, event }`, whose results and which event. It's how a sync finds the session again, even after it's renamed.

**localStorage keys**: `sessions` and `currentSession`; `sessionOrder` (the session names in the select's order); `wcaId` and `wcaLastSync` (WCA sync's ID, and when it last synced, in ms since 1970); `importCompetitor` (whose results were imported last from a competition file); `deviceName` (the name typed in "This device", only while there is one); the settings `main-background`, `secondary-background`, `tertiary-background`, `buttons-background`, `text-color`, `times-color`, `inspectionType`, `inspectionStart`, `delayFlagType`, `timerDisplay`, `timerDecimals`, `timeInsertion`, `totalSolvePhases`; one `visibility-<switch id>` per layout switch (`"show"` or `"hide"`); and `timerWarningConfig_v1` for the timer warnings.

### `main/`

- **`mainController.js`**: the entry point. Imports every controller (including `offline/offlineController.js`), puts the last solve on the timer (`showLastSolve()`), then `await initEvent()`.
- **`cstimer.js`**: runs csTimer's scrambler (`public/cstimer_module.js`) in a web worker, so making scrambles never freezes the page. `call(type, args)` sends `[id, type, args]` to the worker and keeps the promise's `resolve` in `callbacks[id]`; when the worker answers `[id, type, result]`, `onmessage` resolves that promise. It exports `csTimer` with `getScramble(type, length)`, `getImage(scramble, type)` (an SVG picture), `setSeed(seed)` and `setGlobal(key, value)`.

### `timer/`

- **`timerState.js`**: `PHASE` (the timer's phases) and `timerObj` (the current phase, interval and timeout ids, inspection time, timer phases of the solve in progress). `countdownObj` holds the 1-hour countdown for Fewest Moves and Multi-Blind.
- **`timerController.js`**: all keyboard and touch handling. What a press and a release do in each phase:

  | Phase | Press | Release |
  | --- | --- | --- |
  | idle | → inspecting (inspection starts now with "Press start"); with inspection off, straight to the hold | |
  | inspecting | `beginHold` → holding | starts inspection, with "Press end" |
  | holding | | `cancelHold` → back to inspecting or idle |
  | ready | | → running, `startTimer` |
  | running | `handleSplitOrStop` | |

  `onPressLost` cancels a hold when the release can't come (touch cancelled, tab hidden, window blurred). Escape cancels everything and puts the last solve back on the timer. Tab switches between Timer and Typing (`setTimeInsertion`). `setTimerDisplay(colorOrTime, content)` is the only function that writes on the timer; the other timer files get it passed in. `inspection2` is a separate seconds count used for inspection in Typing mode (its own `setInterval`, with `seconds`, `interval` and `running` kept in the file); `stopInspection2()` stops and resets it and shows the last solve again, and does nothing when it isn't running. It stops on a second press, on its own at 17 s, on Escape, and when leaving Typing mode: Tab and the Time insertion select's `change` call `stopInspection2()` right away, and each tick also checks `timerSettObj.timerFlag` and `untimedEvent`, so any other way out of Typing mode (like changing to Fewest Moves or Multi-Blind) stops it on the next second without writing over their countdown. In Typing mode, the space bar, the "Inspection (space)" button and a tap start and stop it, except on Fewest Moves and Multi-Blind. A space typed in another text box (`isTyping()`: "This device", the details pop-up's solution box) is left alone; the typed-time box (`#typed-time`) is the exception, because it has the focus in Typing mode. In Timer mode, keys typed in any text box never reach the timer (`isTyping()`).

  `showLastSolve()` writes the session's most recent solve on the timer: it gets the solve from `getLastSolve` (`session/`) and formats it with its penalty and the "Timer decimals" setting using `formatSolveTime` ("14.34 (+2)", "DNF"), or shows zero (`formatTime(0, decimals)`: "0.0", "0.00" or "0.000") when the session has no solves. On Fewest Moves and Multi-Blind (`timerSettObj.untimedEvent`) it does nothing, because the timer shows their countdown there. If the last solve is a Fewest Moves or Multi-Blind result (moves or points, not a time), it shows zero. Solves are saved with 2 decimals, so with 3 the last digit is always 0: a solve stopped at "12.347" comes back as "12.340". A `change` listener on `#timer-decimals` calls it too, so a new choice shows right away; it only runs while the timer is idle and the typed-time inspection count isn't running, and `settingsController.js`'s listener on the same select runs first (it was added first, since `timerController.js` imports it), so the new value is already in `timerSettObj`. Loading the page (`main/mainController.js`), Escape, the end of `inspection2`, deleting a solve (`removeSolve` in `modal/`), clearing the session (the Clear button in `topbar/`, which then shows "0.00"), switching sessions (the top bar's `sessionChanged` handler, after the event layout has written "0.00") and a WCA sync that added solves to the session in use (`importExport/`, only while the timer is idle, so a solve in progress isn't written over) all call it.
- **`timerPhases.js`**: `beginHold` (red, then green after `HOLD_DELAY_MS`), `cancelHold`, `resetTimerColor`.
- **`timer.js`**: `startTimer` updates the display every 10 ms from `performance.now()` (or shows "Solving" with "Hide while solving"); `stopTimer(…, elapsed)` writes the final time from the `elapsed` ms that `handleSplitOrStop` measured at the press, and goes back to idle. Both read `timerSettObj.timerDecimals` (imported from `settings/settingsState.js`) on every write, so a new "Timer decimals" choice applies right away, even mid-solve.
- **`inspection.js`**: `inspection(type, setTimerDisplay, timerObj)` counts inspection and stores the exact time in `timerObj.inspection`; WCA inspection plays the 8 and 12 second calls and stops at 17.
- **`timeFormatting.js`**: `formatTime(ms, decimals = 2)` for the running timer ("12.34", "1: 02.34", "1: 02: 03.45", or "12.3" / "12.345" with 1 or 3 decimals), truncated like the WCA does by `truncate(n, decimals)` (it never rounds up, so 10.199 is "10.1" or "10.19"; a tiny `1e-6` is added before `Math.floor` so float noise, like `1.13 * 100` being `112.99999999999999`, can't cut a digit). Callers that pass no `decimals` get 2: the saved solve time, each timer phase's time, and csTimer imports. `formatSeconds(seconds, decimals)` does the same for saved seconds (rounded to whole ms first), and `formatSolveTime(solve, decimals)` adds the penalty ("DNF", "12.3 (+2)"), like `formatDisplayTime` does for lists. `timerController.js` re-exports `formatTime` (for `importExport/`, which writes the phases of csTimer solves the same way, and `topbar/`) and `formatSeconds` (for `timeTyping/`).
- **`countdownTimer.js`**: `startTimer2` (start or stop the countdown, playing the ticked warnings from `public/audio/`), `stopTimer2` (reset to one hour), `updateDisplay`.

### `average/`

- **`avgState.js`**: `averageObj` (the mode and the solves of the average in progress) and `classicStats` (classic mode's `current`, `best` and `history` mo3, ao5, ao12 and ao100).
- **`avgController.js`**: `averageOfN(time, scramble, inspection, inspectionType, isFMC, modeFlag, isMBLD, solvePhases, doneWith)`. It turns the input into a value (seconds, moves or points), applies the penalties (WCA inspection: 15 s is +2, 17 s is DNF; an unsolved FMC cube or 0 points or less is DNF), saves the solve with its `doneAt` (`deviceSettObj.name || deviceSettObj.detected`, imported from `settings/settingsState.js` and read on every solve, so a new name counts from the next solve without a reload) and its `doneWith` as the caller gives it (left `undefined` by FMC and Multi-Blind, so it isn't saved), and returns a finished block (`buildAverageBlock`) when the mode has enough solves (`getNeededSolves`), removing those solves from the buffer. With `modeFlag` it adds no solve and only re-checks the buffer after a mode change. It also re-exports the helpers below.
- **`avgComput.js`**: `computeAverage(solves, mode)` returns `{ dnf, avg, best, worst, sigma }`. A DNF counts as `Infinity`, so it sorts last.

  | Mode | Result | It's a DNF when |
  | --- | --- | --- |
  | ao5 | Drop best and worst, mean of the middle 3 (with 4 solves done it also gives the best and worst possible ao5) | 2 or more DNFs |
  | mo3 | Mean of 3 | any DNF |
  | bo3 | Best single; `avg` is the mean of the successful attempts | all 3 are DNF |
  | bo5 | Best single; `avg` is the ao5 of the same solves | all 5 are DNF (the best is then a DNF) |
  | fmc3 (ao3) | Mean of 3 move counts | 2 or more DNFs |
  | ao12, ao100 | Drop the best and worst 5% each, rounded up (1 for ao12, 5 for ao100), mean of the rest | more DNFs than that (2 for ao12, 6 for ao100) |

  For Multi-Blind, more points is better, so `bestAndWorst` flips the comparison.

  `buildAverageBlock(solves, mode)` makes a finished average block from its solves: it runs `computeAverage`, formats the numbers for display (`formatSecondsToTime`, "DNF" for a DNF average) and keeps a copy of the solves. `averageOfN` uses it when a block fills up, and so do the imports and WCA sync (`addSolvesToSession` and `addRoundsToSession` in `session/`, `buildSession` and `buildRoundsSession` in `importExport/`), so imported blocks look exactly like timed ones.
- **`classicAvgs.js`**: `updateClassicStats(recomputeBest, averageObj, classicStats)`. After a new solve, it adds the rolling averages ending at that solve and updates the bests; with `recomputeBest` it rebuilds the whole history by sliding a window over every solve (after a penalty, a removed solve, a session change or switching to classic).
- **`avgHelper.js`**: `parseTimeToSeconds` ("1:02.50" → 62.5), `formatSecondsToTime` (62.5 → "1:02.50", Infinity → "DNF"), `formatDisplayTime` (a solve with its penalty: "14.34 (+2)"), `isPointsSolves` (true for Multi-Blind solves), `getNeededSolves(mode)` (how many solves finish a block: 5 for ao5 and bo5, 12 for ao12, 3 for mo3, bo3 and ao3).

### `session/`

- **`sessionState.js`**: `sessionsObj`: every session by name (from localStorage), the current session's name, `order` (the session names in the select's order, from localStorage's `sessionOrder`) and the session select.
- **`sessionController.js`**: `getCurrentSession`, `saveSessions` (copies the average in progress into the session's `buffer`, then saves all sessions and their order), `renderSessionSelect`, and the select's actions under the divider: New, Rename, Move up / down and Delete.
  - Session order: the select lists sessions by `getSessionOrder()`, not by the keys of `sessionsObj.sessions`. A separate list is needed because JavaScript always puts number-like keys first (csTimer's never-renamed sessions are called "1", "2"…), so reordering the object's keys can't move them. `getSessionOrder` keeps the order in step with the sessions: it drops names that are gone and adds new ones (New, imports, WCA sync) at the end, so nothing that adds or deletes sessions has to update the order itself. Rename swaps the old name for the new one in the order, so the session keeps its place.
  - Move up / down: the "▲ Move current up" (`__up__`) and "▼ Move current down" (`__down__`) options call `moveSession(step)`, which swaps the current session with the one above (`-1`) or below (`1`), saves, and redraws the select so it shows the current session again. `renderSessionSelect` greys out Move up on the first session and Move down on the last.
  - Delete moves to the first session in the select's order. It switches with `switchSession(first, true)`, skipping the save (`saveSessions` would write the solves in progress into the deleted session), then calls `saveSessions()` once the new session's solves in progress are loaded, so the deletion is stored and the session doesn't come back on reload. `switchSession` saves, changes session and fires a `sessionChanged` event, which the top bar answers by loading the new session (`changedSession` copies its buffer and classic stats into the shared state) and setting its selects. `clearAverages` empties the session after asking. The other functions (including `addSolvesToSession`, used by the import) pass the session state to `solve.js`. `switchSession` is exported too, so an import can open the first session it added.

  `addRoundsToSession(name, rounds)` (WCA sync) is the one wrapper that works on any session, not only the current one, and returns how many solves were new. The current session's solves in progress live in `averageObj`, so for it, it passes `averageObj` and `getCurrentSession`. Classic mode then recounts its rolling averages (`updateClassicStats(true)`), and the session keeps a copy of them. Any other session keeps its solves in progress in its `buffer`, which has the same shape (`mode`, `solveCounter`, `solvesArray`), so it passes that buffer (making an empty one if the session has none yet) and `() => session`. A classic session's saved `classicStats` are then out of date, so they're deleted, and `changedSession` rebuilds them when you open the session.
- **`solve.js`**: `addAverageBlock`, `getSessionAverages`, `getLastSolveTarget` (the most recent solve: the last one of the average in progress or the last one of the newest saved average, whichever has the later `createdAt`; a solve saved without `createdAt` counts as 0, so the average in progress wins ties), `getLastSolve` (the solve object `getLastSolveTarget` points at, or `null`; the timer shows it), `getLastTwoSolves` (the two most recent solves, oldest first, as `[previous, last]`, or fewer when the session has fewer: it takes the last two solves of the newest saved average and of the average in progress and sorts them by `createdAt` with `byDate`, which is enough because the two newest solves can only be at one of those two ends; on a tie the average in progress stays last, like in `getLastSolveTarget`; the difference beside the timer uses it), `penalty2` (change a solve's penalty; a saved solve's block is recomputed), `remove2` (remove a solve; it always asks first: a solve of the average in progress is removed alone (OK) or together with every other solve in progress (Cancel, then a second confirmation), and a solve from any finished average, the newest one too, either reopens that average without it (OK) or deletes the whole average (Cancel, then a second confirmation). Reopening never replaces the solves in progress: the average's other solves join them by date through `joinInProgress`, so with solves already in progress a block mode can close a new average right away, and the dialog says the solves in progress are kept), `applyPenaltyToLast` and `removeLastSolve` (the buttons under the timer). In `penalty2` and `remove2`, a `blockIndex` of -1 means a solve of the average in progress (`averageObj.solvesArray`), and any other number is the index of a saved average in `session.averages`.

  `addSolvesToSession(solves, averageObj, getCurrentSession)` adds solves from an import to the current session and returns how many were new:
  1. It skips solves the session already has, finished or in progress. Two solves are the same when they have the same `createdAt` and `time` (`solveKey`), so importing a file twice adds nothing; a solve twice in the file counts once.
  2. It hands the new solves to `joinInProgress(solves, averageObj, session)`, which steps 3 to 5 are about. `remove2` also uses it when an average is reopened, without step 1, so an old solve saved without `createdAt` is never mistaken for a copy and dropped.
  3. The solves join the average in progress, and all of them are sorted oldest first (`byDate`). None of the solves already in progress is replaced.
  4. In a block mode, every whole block of the current mode becomes a finished average (`buildAverageBlock`), oldest first, and the leftovers stay in progress. `session.averages` is then sorted newest first by each block's newest solve (`blockDate`), so new averages sit among the old ones by date.
  5. In classic mode every solve stays in progress, since classic has no blocks.

  `addRoundsToSession(rounds, averageObj, getSession)` adds competition rounds, `[{ mode, solves }]`, to a session (WCA sync) and returns how many solves were new. Like `addSolvesToSession`, it works on any session whose solves in progress are passed as `averageObj`:
  1. It gathers the keys (`solveKey`) of every solve the session already has, finished or in progress.
  2. A round with a `mode` whose solves are all new becomes its own finished average in that mode (`buildAverageBlock`), like `buildRoundsSession` makes it: a round deleted from the session comes back as it was.
  3. The new solves of every other round (no `mode`, or some of its solves are already there) go through `addSolvesToSession`. When you delete one solve of the newest round and pick OK (reopen), `remove2` puts its other solves back in progress (`joinInProgress`), so the missing one joins them and the average closes again.
  4. `session.averages` is sorted newest first (`blockDate`), also in classic mode, where `addSolvesToSession` doesn't sort.

### `modal/`

- **`modalController.js`**: `openDetailsModal()` opens the pop-up (the Open Session button). The first card is the average in progress, if it has solves.   - Every solve row is built by `solveRowHtml(solve, index, blockIndex, dropped)` as a `<details>` element, which the browser opens and closes on its own, with no JavaScript. Its `<summary>` is the one line always shown: number, time (in parentheses when `dropped`) and the start of the scramble, cut with "…" by the CSS. Opening it shows the penalty and Share buttons, scramble, inspection, date (`shortDate`, like "01/11/2026, 09:22"), "Done at" (only when the solve has a `doneAt`, so older solves and lists of times show no empty line), "With" (only when it has a `doneWith`) and, for 3x3, a solution box. Its buttons carry `data-block` and `data-solve`, and a `data-block` of -1 marks a solve of the average in progress; `blockSolves(blockIndex)` turns that into the solves list (the buffer's or the saved average's).
  - **Sharing**: `cardHtml` keeps each card's header and stats HTML in `modalCardHeaders` by `blockIndex`. An average's Share button calls `shareAverage`, which gives them, the solves and the mode to `averageShareText`; a solve's calls `shareSolve`, which uses `solveShareText`. Both hand the text to `shareOrCopy` and show how it went on the button for `SHARE_FEEDBACK_TIME` (1.5 s) with `showShareResult` ("Copied", "Shared" or "Couldn't copy"; closing the share sheet shows nothing).
- **`shareText.js`**: the text for sharing, and sending it.
  - `htmlToText(html)` turns the modal's HTML (header, stats line, `formatStatValue`'s time) into plain text with `DOMParser`, which builds an inert document, so nothing in it runs. Reusing that HTML keeps the shared numbers and units ("31 moves", "4/5 (3 pts)") the same as the modal's.
  - `shortDate(ms)` is the date without seconds or time zone, in the browser's language, or "-" for old solves without one. The modal uses it too.
  - `droppedIndexes(solves, mode)` gives the indexes of the solves a full ao average drops: the fastest and slowest 5%, rounded up (1 each for an ao5), like `computeAverage`. It sorts the indexes by final value (time plus penalty, Infinity for a DNF). Other modes, and an average still in progress, drop none.
  - `averageShareText(titleHtml, statsHtml, solves, mode)`: "Pro Timer · <event>" (`introLine`, the event's name from `getEventName`), the header and the stats, then a blank line and each solve numbered, with dropped times in parentheses. `solveShareText(s)` is the intro line, then one solve. Each solve's lines come from `solveLines`: its time, then everything the modal shows.
  - `shareOrCopy(text)` opens the share sheet (`navigator.share`) when the main pointer is a finger (`(pointer: coarse)`, phones and tablets; a touch-screen laptop's is still the mouse), else copies with `copyText`. It returns `"shared"`, `"copied"`, `"cancelled"` (share sheet closed) or `"failed"`, and falls back to copying if sharing fails for another reason. `copyText` uses `navigator.clipboard`, which only exists on https and localhost. Elsewhere (the dev server opened from a phone by its IP) it copies from a hidden `<textarea>` with the older `execCommand("copy")`. `setPenalty` and `removeSolve` change a solve, recount the classic rolling averages, save, redraw the history and refresh the pop-up with `refreshDetailsModal()`. `removeSolve` also puts the new last solve on the timer (`showLastSolve` from `timer/`); the X button under the timer goes through it too. `submitSolution` checks a typed solution on cubisz and saves its move count, TPS and status on the solve, in the buffer or in its saved average.

### `timeTyping/`

- **`timeTypingController.js`**: the Add button and the Enter key save a typed time. `normalizeTypedTime` accepts "12.34", "1:02.50" or digits only ("1234" → 12.34, "10234" → 1:02.34); anything else flashes the box red. The time is shown on the timer with `formatSeconds` (from `timer/timerController.js`) and the "Timer decimals" setting, like a timed solve, and goes to `averageOfN` with `doneWith` "Typing".

### `importExport/`

The Data section of the settings panel. **Export** downloads every session as one `.json` file. **Import** reads a file from Pro Timer, csTimer, CubeDesk or Twisty Timer, or a list of times, and adds its solves. The **WCA sync** row keeps a competitor's official results from the WCA website in "WCA <event>" sessions: **Sync** asks in the import pop-up which events and where, and the app syncs the existing WCA sessions on its own once a day, with no pop-up. None of them ever replaces or deletes anything.

How a file import goes:

1. **Import** clicks the hidden `<input type="file" id="importFileInput">`, which opens the browser's file picker (`.json`, `.txt` and `.csv` files).
2. On the input's `change`, the controller reads the file as text (`file.text()`) and empties the input, so picking the same file again still fires `change`.
3. The handler parses the text once (`parseJSON`, `null` when it isn't JSON) and turns it into **choices** for the pop-up, `[{ label, source, imported }]`, where `imported` is a list of sessions in Pro Timer's shape, `[{ name, session }]`. A competition file (`detectFormat` gives `"wcif"`) has everyone's results, so it gives one choice per competitor (`competitorChoices`). Any other file is one choice, from `sessionsFromFile(text, data, fileName)`: a JSON file is recognised by its keys (`detectFormat`), any other file by its first line (`detectTextFormat`), and each format has its own reader (table below). Anything that's none of them is read as a list of times; a file with no time in it either throws an Error, and the handler shows its message in an alert.
4. `importSessions(choices)` stops with an alert when there's nothing to import. Otherwise `askImport` opens the import pop-up: whose results (only with several competitors), which sessions (all of them or just one, only asked when there are 2 or more) and where they go. Cancel or Escape stops here.
5. **New sessions** calls `addImportedSessions`, **Current session** calls `addIntoCurrentSession`, with the chosen sessions.

How a WCA sync goes (`syncWca(quiet)`, from **Sync**, Enter in the WCA ID box, or the daily sync on load with `quiet` on):

1. An empty box stops syncing: the saved ID and last sync are forgotten (the sessions keep their `wcaSync` mark, so typing the ID again finds them). Anything that isn't a WCA ID (`cleanWcaId`) stops with a message, and a valid one is written back cleaned up ("2009zemd01 " → "2009ZEMD01").
2. The button is disabled and the status line says "Syncing…" while it fetches the results (`fetchWcaPerson`). They're read by event (`readWcaResults`), and the competitor's name is taken from the first result (only the ID when they have no results).
3. **The daily sync (`quiet`)** goes straight to `syncIntoWcaSessions` with `createMissing` off, so it only fills WCA sessions that already exist. The pop-up is where you pick which events get a session, and the daily sync doesn't undo that choice. A new event you compete in gets its session the next time you press Sync.
4. **The Sync button** puts "Last synced …" back on the status line, builds each event as a session (`buildRoundsSession`, keeping its `event` and `rounds` next to it), and opens the import pop-up through `importSessions`, with "<name>'s WCA profile" as the source. The non-current choice reads "WCA sessions (new solves only)" and calls `syncIntoWcaSessions` with `createMissing` on. **Current session** is a plain import (`addIntoCurrentSession`, with its own confirm and alert), which doesn't save the ID or the time. Cancel changes nothing.

`syncIntoWcaSessions(wcaId, person, events, createMissing)` does the sync itself:

1. `saveSessions()` puts the average in progress in its session. It runs after the fetch and the pop-up, since you can time a solve while it downloads. It also leaves the state from before the sync in localStorage, in case saving fails later.
2. For each event, `wcaSession` finds its session. If there is one, `addRoundsToSession` (`session/`) adds the solves it doesn't have yet. If not, and `createMissing` is on, `buildRoundsSession` makes one, marked with `wcaSync`, under a free name (`uniqueSessionName`).
3. `saveSessions()` again. When the storage is full it throws: the sessions are read back from localStorage (the state of step 1), `changedSession()` reloads the session in use from them, and it throws "Not enough space…".
4. Redraw: the session select gets any new sessions (`renderSessionSelect`), and when the session in use got new solves, the history (`renderHistory`) and, while the timer is idle, the timer (`showLastSolve`).
5. The ID and the time (`wcaId`, `wcaLastSync`) are saved, and the status line says "Last synced <date> (<name>: N new solves)". The competitor's name shows a mistyped ID right away.

Any error (a bad ID, no internet, an ID nobody has, full storage) is written in the status line, and also shown in an alert unless `quiet`. A full storage inside the pop-up's choice reaches the same `catch`, since `importSessions` is awaited. The ID and `wcaLastSync` are only saved after a sync into the WCA sessions that worked, so a failed daily sync tries again the next time the app opens. `finally` turns the button back on, whatever happened, so it stays disabled while the pop-up is open.

Since solves are matched by date and time (`solveKey`), and a WCA attempt's date is worked out the same way every time (`attemptDate`), a sync only adds what's new. Two things follow: a WCA solve you delete comes back on the next sync, and a result the WCA corrects later (a different time) is added next to the old one.

- **`importExportController.js`**:
  - `dataDOM`: the Data section's buttons, file input, WCA ID box and WCA sync status line (`#wcaSyncStatus`), and the import pop-up's elements (the dialog, its info line, the sessions row and select, the target select and its two options: `newOption`, whose text says what it does, and `currentOption`, which gets the session's name).
  - Export: `saveSessions()` first, which copies the average in progress into its session's `buffer`, then `downloadJSON(buildExportFile(sessionsObj.sessions), exportFileName())`.
  - `sessionsFromFile(text, data, fileName)`: the sessions of any file but a competition file (step 3 above). `data` is the already parsed JSON, so big files aren't parsed twice. `fileName` without its extension names the session of a CSV or a list of times, since those files don't name it.
  - `competitorChoices(data)`: a competition file's competitors with results (`readWcifFile`), each as a choice: `label` is the name with the WCA ID (newcomers have none yet), `source` is "<name> at <competition>", and `imported` their sessions (`toRoundSessions`).
  - `toRoundSessions(events)`: events made of competition rounds, `[{ name, event, rounds }]`, as Pro Timer sessions with `buildRoundsSession`, in the event's WCA average mode and first category. Used by competition files (WCA sync calls `buildRoundsSession` itself, since it also marks the session).
  - `toSessions(looseSessions)`: what every reader but Pro Timer's gives, `[{ name, event, solves }]`, as Pro Timer sessions: each becomes `buildSession(solves, event, getDefaultModeForEvent(event), getCategoryOfEvent(event))`, so it lands in its event's WCA average mode (`topbar/`) and in the first category that lists the event (`scramble/`).
  - `importSessions(choices, newLabel, addNew)`: steps 4 and 5 above, shared by files, competition files and the WCA Sync button. Each choice's `source` says where the sessions come from in the pop-up and alerts ("This file", "Feliks Zemdegs at Puzzling Pakenham Sunday 2026", "Feliks Zemdegs's WCA profile"). `newLabel` is the text of the non-current choice and `addNew` what it does; they default to "New sessions" and `addImportedSessions`, so files call it with `choices` alone, and the WCA sync passes "WCA sessions (new solves only)" and a function that calls `syncIntoWcaSessions`.
  - `showChoice({ source, imported })`: writes what a choice holds in `#importInfo` (how many sessions and solves, or the name of its only session), fills `#importSessionSelect` with "All sessions (N solves)" (value `all`) and one option per session with its solve count (value: its index in `imported`), and hides that row (`#importSessionRow`) when there's only one session, leaving it on "All sessions".
  - `askImport(choices, newLabel)`: fills `#importCompetitorSelect` with one option per choice (value: its index) and hides its row (`#importCompetitorRow`) unless there are 2 or more, so only competition files show it. It starts on the competitor imported last time (their label is kept in localStorage under `LAST_COMPETITOR_KEY`, since people mostly import their own results), else the first, and shows that choice (`showChoice`). Picking another competitor shows theirs; the handler is set with `onchange` rather than `addEventListener`, so each opening replaces the last one's instead of piling up. It writes the session in use into the "Current session" option of `#importTarget` and `newLabel` into the other one (set on every opening, since files and the WCA sync share the same `<option>`; its value stays `"new"`), then opens `#importDialog` with `showModal()`. It returns a Promise that resolves when the dialog's `close` event fires: with `{ chosen, target }` (`chosen` is every session of the competitor on show or `[the one picked]`, `target` is `"new"` or `"current"`), or with `null` when the dialog's `returnValue` isn't `"import"`. The target select keeps its choice for the next import. The two buttons sit in a `<form method="dialog">`, so clicking one closes the dialog with that button's `value` as the `returnValue`. Escape closes it without a value, keeping the old one, so `returnValue` is cleared before each opening. `importSessions` `await`s this Promise before adding anything.
  - `addImportedSessions(imported)`: asks first (how many sessions and solves), adds each session under a free name (`uniqueSessionName`), saves, and opens the first one with `switchSession` (`session/`), whose `sessionChanged` event makes the top bar load it and redraw. The browser keeps about 5 MB per site, and `saveSessions()` throws a `QuotaExceededError` when that's full: then the new sessions are removed again, so nothing stays half-imported.
  - `addIntoCurrentSession(imported)`: gathers every solve of the chosen sessions (`sessionSolves`), asks first, keeps copies of `session.averages` and the average in progress, and calls `addSolvesToSession` (`session/`). Classic mode then recounts its rolling averages (`updateClassicStats(true)`), and the session keeps a copy of them. If saving throws, the copies are put back. Last, it redraws the history (`renderHistory`), shows the newest solve on the timer (`showLastSolve`) and says how many solves were added and how many were already there. The solves keep their own `event`, which the history and details pop-up read (for example to show moves for an FMC solve, or the solution box for 3x3 ones).
  - `WCA_ID_KEY` (`"wcaId"`) and `WCA_LAST_SYNC_KEY` (`"wcaLastSync"`): the localStorage keys of the ID that syncs and of when it last synced.
  - `wcaSession(wcaId, event, name)`: the name of the session a sync fills with a competitor's event, or `null` when there's none yet. First it looks for a session marked `wcaSync: { wcaId, event }`, whatever it's called now: renaming keeps the same session object under a new key, so the mark goes with it. Else it adopts a session named exactly `name` ("WCA 3x3x3") with the same event and no mark, which is what the one-time WCA import before sync made, and marks it. A session marked for another WCA ID is never adopted, so syncing a second competitor makes their own sessions ("WCA 3x3x3 (2)").
  - `showLastSync(note)`: writes "Last synced <date>" in the status line, the date and time in the browser's language (`toLocaleString` with `dateStyle: "medium"` and `timeStyle: "short"`), plus the note in brackets when given; empty when it never synced.
  - `wcaSyncFailed(message, quiet)`: writes why a sync failed in the status line, and also shows it in an alert unless `quiet`.
  - `syncIntoWcaSessions(wcaId, person, events, createMissing)`: adds the events' new solves (`[{ name, event, rounds }]`) to the competitor's WCA sessions, creating the missing ones only when `createMissing`, then saves, redraws and remembers the sync (its steps 1 to 5 above). It throws on a full storage.
  - `syncWca(quiet)`: the WCA sync, steps 1 to 4 above. The Sync button calls it through an arrow function (`() => syncWca()`), since `addEventListener` would otherwise pass the click event as `quiet`. It imports `timerObj` and `PHASE` (`timer/timerState.js`) to check the timer is idle before writing on it.
  - Startup (the last lines): puts the saved ID in the box and shows the last sync (`showLastSync()`), then calls `syncWca(true)` when there's an ID, `navigator.onLine` is true, and `wcaLastSync` is more than a day ago (`DAY`; 0 when it never synced). It's at the bottom of the file because it reads the `const` keys declared above it.
- **`exportSolves.js`**: `buildExportFile(sessions)` wraps the sessions with a tag, a version and the date. `downloadJSON(obj, filename)` saves an object as a file: it puts the JSON text in a `Blob`, makes a temporary URL for it (`URL.createObjectURL`), clicks a link with the `download` attribute, then frees the URL. `exportFileName()` gives `pro-timer_YYYY-MM-DD.json` with the local date.
- **`importSolves.js`**: the Pro Timer side and the helpers every format uses.
  - `parseJSON(text)`: the object, or `null` when the text isn't JSON.
  - `detectFormat(data)`: for JSON files, `"protimer"` (an `app: "Pro Timer"` tag and a `sessions` object), `"cstimer"` (a key like `session1`), `"wcif"` (a `formatVersion` text with `persons` and `events` lists), `"cubedesk"` (`sessions` and `solves` lists, or the old `timer.sessionMap`) or `null`.
  - `detectTextFormat(text)`: for other files, from the first line (without the byte order mark some editors add): `"twistytimer"`, `"cstimercsv"`, or `"timelist"` for anything else.
  - `parseCsv(text, separator)`: the rows of a CSV text as lists of fields. It reads character by character, since a quoted field can hold the separator, a newline (Twisty Timer's Megaminx scrambles) or a doubled quote (`""`). Empty lines are skipped, and `\r\n` line ends work too.
  - `msToSeconds(ms)`: milliseconds as seconds cut to hundredths, like the timer saves them. `toHundredths(seconds)` does the same for seconds with more decimals, going through whole milliseconds first, since `10.05 * 100` is `1004.99…` in floating point and would become 10.04.
  - `importedSolve({ time, penalty, scramble, event, createdAt, result, solvePhases, doneAt })`: a Pro Timer solve from another app. What no export has is filled in like a typed time (`inspection` 0, `solution` null); `result` (Multi-Blind), `solvePhases` and `doneAt` (the app's or the competition's name) are only added when given.
  - `readProTimerFile(data)`: `[{ name, session }]`. It throws when `version` is above 1 (a newer Pro Timer made the file and may save solves differently), skips anything that isn't a session object, and gives a session with no `averages` an empty list.
  - `sessionSolves(session)`: every solve of a session, the finished averages' first, then the buffer's. `countSolves(session)` is its length.
  - `uniqueSessionName(name, sessions)`: the name itself when it's free, else the first free "name (2)", "name (3)"…
  - `buildSession(solves, event, mode, category)`: a session from loose solves. It sorts them oldest first, cuts whole blocks of `getNeededSolves(mode)` solves with `buildAverageBlock` (what `averageOfN` does while you time), puts the blocks newest first in `averages` and the leftover solves in `buffer`, and sets `category`, `scrambleType` and `mode`. `category` must be a category that lists the event, or the top bar's event select ends up empty.
  - `buildRoundsSession(rounds, event, mode, category)`: a session from competition rounds, `[{ mode, solves }]`. A round with a `mode` becomes one finished average in that mode (`buildAverageBlock`), so a bo3 round stays a bo3 even in a bo5 session (sessions can mix modes, like after you change the mode). The solves of rounds with no `mode` go through `buildSession`, so they're grouped by date in the session's mode, and the last few may be the average in progress. All the averages are then sorted newest first (`newestSolveDate`).
- **`wcaImport.js`**: a competitor's official results from the WCA's public API (`https://www.worldcubeassociation.org/api/v0`, no sign-in, and it answers other sites' pages). It only fetches and converts; the controller wires it.
  - `cleanWcaId(text)`: the ID trimmed and in capitals, or `null` when it isn't 4 digits, 4 letters and 2 digits (`WCA_ID`).
  - `fetchWcaPerson(wcaId)`: `{ results, competitions }`, the two requests sent together (`Promise.all`). `fetchPersonData(wcaId, part)` sends one, and turns failures into messages: `fetch` throwing means no answer (offline), 404 means no competitor has that ID, anything else not OK is an error from the WCA website.
  - `readWcaResults(results, competitions)`: `[{ name, event, rounds }]`, one entry per event in `WCA_EVENTS` order, leaving out events the competitor never did. Each result (one per round) becomes a round: its attempts, minus the `0`s (attempts not done after a missed cutoff), converted with `convertWcaAttempt`, and its `mode` from `roundMode`. Two maps by competition id come from `competitions`: `startDates` (each attempt's date) and `names` (`short_name`, else `name`: each attempt's `doneAt`); a competition missing from them counts as today, named by its id (with sync, that would add its solves again on each new day; the API has always listed every competition in testing).
  - `WCA_EVENTS`: `[WCA id, Pro Timer event, name]` for each event, exported for `wcifImport.js`. Sessions are named "WCA " + the name here, and "<competition> " + the name for competition files. It's a list, not an object, because an object puts number-like keys ("222", "333") first. Magic, Master Magic and old Multi-Blind aren't in Pro Timer, so they're left out; 3x3 With Feet is (`333ft`).
  - `roundMode(formatId, attemptCount)`: the average a round fills: `ao5` (format `a`, 5 attempts), `mo3` (`m`, 3; also for FMC, since the WCA mean is a DNF with one DNF, unlike Pro Timer's `fmc3`), `bo3` (`3`, 3), `bo5` (`5`, 5). Anything else (a missed cutoff, a best of 1 or 2, a format Pro Timer doesn't have) is `null`.
  - `convertWcaAttempt(value, wcaEvent, event, createdAt, doneAt)`: one attempt as a solve (table below); `doneAt` is the competition's name, given by `readWcaResults` and `readWcifFile`.
  - `decodeMultiBlind(value)`: WCA's Multi-Blind number `0DDTTTTTMM` as `{ points, result }`: points are 99 − DD, MM is the cubes missed, solved is points + missed, and `result` is "solved / attempted" like Pro Timer's own Multi-Blind.
  - `attemptDate(startDate, eventIndex, roundType, attemptIndex)`: the WCA keeps no times of day, so an attempt is dated the competition's first day at 8:00 local time, plus 20 minutes per event (`WCA_EVENTS` order), a minute per round (`ROUND_ORDER`: qualification, first, second, semi final, B final, final) and a second per attempt. That keeps rounds and attempts in order, and no two attempts share a date, which `addRoundsToSession` and `addSolvesToSession` use to skip solves a session already has. Every sync works out the same dates, as long as the time zone and `WCA_EVENTS` / `ROUND_ORDER` don't change, so it only adds what's new.
- **`wcifImport.js`**: a competition's WCIF file (WCA Competition Interchange Format), the JSON WCA Live imports from the WCA website and syncs results back with. It holds every competitor, so it's read for all of them, and the pop-up asks whose to import. Attempts use the same numbers as WCA results, so it reuses `WCA_EVENTS`, `convertWcaAttempt` and `roundMode` from `wcaImport.js`.
  - `readWcifFile(data)`: `[{ name, wcaId, competition, events: [{ name, event, rounds }] }]`, the competitors with at least one attempt, sorted by name. `competition` is the short name, used in session names and as every solve's `doneAt`. Each round's results are looked up by competitor first (`resultsByRound`: round id → `personId` → result, where `personId` is the competitor's `registrantId`), so it doesn't search every result for every competitor. An attempt's number is `value` in WCIF 2 (WCA Live) and `result` in WCIF 1 (the WCA website); `0` is an attempt not done (a missed cutoff, or not entered yet).
  - Dates come from the schedule: a round starts when the competitor's group did (`groupStart`, from their `"competitor"` assignments, when the file has groups), else when the round did (`roundStarts`, the earliest room), else at a made-up time (`fallbackStart`: the first day at 8:00, 20 minutes per event, a minute per round). Each attempt is then a second after the one before, to keep them in order.
  - `scheduleActivities(schedule)`: every activity of every room, with the groups inside them at any depth, by id.
- **`cubeDeskImport.js`**: CubeDesk's "Export data" file.
  - `readCubeDeskFile(data)`: `[{ name, event, solves }]`. Sessions are taken in CubeDesk's order (`order`), and each session's solves are grouped by CubeDesk event: a session with one event keeps its name, one with several becomes one session per event ("Main 3x3", "Main 4x4"), since a Pro Timer session has one event. Solves with no session (CubeDesk's trainer solves) are skipped. Very old exports call the event `cube_type` instead of `event_type`.
  - `cubeDeskData(data)`: `{ sessions, solves }`. The current export already has them; the old one (`timer.sessionMap`) keeps each session's solves by event, each solve a list of values in `LEGACY_FIELDS` order, which this turns into objects.
  - `convertCubeDeskSolve(solve, event)`: one solve (table below). `cubeDeskDate(solve)` is when it ended, else started, else was saved, accepting dates saved as text.
  - `CUBEDESK_EVENTS`: CubeDesk's events as `[Pro Timer event, name]`; custom events import as 3x3.
- **`twistyTimerImport.js`**: Twisty Timer's (Android) backup.
  - `readTwistyTimerFile(text)`: `[{ name, event, solves }]`, one session per puzzle and category, in the order they first show up. Lines with no puzzle or no time are skipped.
  - `convertTwistySolve(millis, date, scramble, penalty, event)`: one solve (table below).
  - `TWISTY_PUZZLES`: Twisty Timer's puzzles (`222` … `777`, `mega`, `pyra`, `skewb`, `clock`, `sq1`) as `[Pro Timer event, name]`.
- **`textImport.js`**: text files of times, which don't say which event they're for, so they import as 3x3 (`TEXT_EVENT`).
  - `parseTimeText(text)`: a time as timers write it, as `{ time, penalty }`, or `null`: "12.34", "1:02.34", "DNF", "DNF(12.34)" (the time it stopped at), "14.34+" (csTimer's +2, with the 2 seconds already added, so it becomes 12.34 with a +2). `clockToSeconds` requires decimals, so a line number like "3" or a year isn't read as a time.
  - `readCsTimerCsv(text, name)`: csTimer's CSV of one session (`No.;Time;Comment;Scramble;Date;P.1…`). The phase columns (`P.1`, `P.2`…) become `solvePhases` when a solve has more than one.
  - `readTimeList(text, name)`: every line goes through `lineSolves`, so a list can mix styles; lines that aren't times (titles, stats like "mean of 5: 12.34") are skipped. A line is either `time;scramble;date[;DNF]` (`;` or tab: Twisty Timer's single-puzzle export, spreadsheets), `time, time, time`, or `[1.] time [scramble]` (csTimer's copied list).
  - `parseDate(text)`: a date in ms, or `null`. csTimer's "2026-10-31 14:07:09" gets a "T" in the middle, since not every browser reads it with a space.
  - `fillMissingDates(solves)`: solves without a date get one, a second apart in the file's order, the last one just now. So importing the same dateless list twice adds it twice: there's no date to recognise the solves by.
- **`csTimerImport.js`**: the csTimer side. It only converts data; the controller wires it.
  - `readCsTimerFile(data)`: `[{ name, event, solves }]`, one entry per `sessionN` key, in the file's order. The name and scramble type come from `properties.sessionData` (key `N`). Records that aren't solves are skipped (a damaged file), and sessions with no solves are left out, since csTimer always has a `session1`.
  - `proTimerEvent(scrType)`: Pro Timer's event codes are csTimer's scramble types (`scramble/scrData.js` is csTimer's list), so most types map as they are. It gives `"333"` when the type is missing, when Pro Timer doesn't list it (`getCategoryOfEvent` returns `null`), or when it's in `CLOCK_TIME_ONLY` (`333fm`, `r3ni`). csTimer saves clock times in those two, while Pro Timer saves moves and points there, so a time would be read as a move count or points.
  - `convertCsTimerSolve(record, event)`: one csTimer solve as a Pro Timer solve (table below).
  - `csTimerPhases(times)`: each phase's own time, first phase first, written with `formatTime` (`timer/`) like the timer writes them. It reverses csTimer's splits into phase end times, then takes each end minus the one before it.
  - `unwrapJSON(value)`: csTimer saves `sessionData`, and sometimes a session's solves, as JSON text inside the JSON file. This parses text and keeps anything else as it is.

**Pro Timer's file** (`pro-timer_YYYY-MM-DD.json`): `{ app: "Pro Timer", version: 1, exportedAt, sessions }`. `sessions` is `sessionsObj.sessions` as it is (see [Data](#data)), and `exportedAt` is when the backup was made (ms since 1970). Raise `version` if the shape ever changes, so an older Pro Timer refuses the file instead of misreading it.

**csTimer's file** ("Export to file", `cstimer_YYYYMMDD_hhmmss.txt`, JSON inside):

- `session1`, `session2`…: each session's solves, as a list or as the same list in JSON text.
- `properties.sessionData`: JSON text, `{ "1": { name, opt: { scrType }, … }, … }`. A session never renamed has its number as its name, and no `scrType` means 3x3.
- One solve is `[[penalty, ms, …splits], scramble, comment, unixSeconds]`, which becomes:

| csTimer | Pro Timer |
| --- | --- |
| `penalty`: `0`, `2000` (ms added), `-1` | `penalty`: `null`, `2`, `"DNF"` |
| `ms`, the time without the penalty | `time`: `Math.floor(ms / 10) / 100`, seconds cut to hundredths like the timer |
| splits `[total, end of phase n-1, …, end of phase 1]` (when each phase ended, last phase first) | `solvePhases`: each phase's own time, first phase first; one entry for a solve without phases |
| `scramble` | `scramble` (and `event` from the session's scramble type) |
| `comment` | not kept, since Pro Timer solves have no comment |
| `unixSeconds` | `createdAt`: × 1000 |
| (no inspection saved) | `inspection`: 0, like typed times |
| (the app) | `doneAt`: "csTimer" |

**WCA results** (`/persons/<WCA ID>/results` and `/persons/<WCA ID>/competitions`): one result per round, `{ competition_id, event_id, round_type_id, format_id, attempts, … }`, and one competition per entry, `{ id, name, short_name, start_date, … }`. Each attempt becomes:

| WCA | Pro Timer |
| --- | --- |
| centiseconds (most events) | `time`: ÷ 100 |
| moves (`333fm`) | `time`: the moves, like Pro Timer's FMC |
| `0DDTTTTTMM` (`333mbf`) | `time`: the points, `result`: "solved / attempted", DNF under 1 point |
| `-1` (DNF), `-2` (DNS) | `penalty`: `"DNF"` and `time` 0, since the WCA keeps no time for them; a DNS counts as a DNF, like in WCA averages |
| `0` | no solve: an attempt not done (after a missed cutoff) |
| competition's `start_date`, event, round, attempt number | `createdAt` (`attemptDate`) |
| (no scramble per competitor) | `scramble`: empty |
| competition's `short_name` (else `name`) | `doneAt` |

**A competition's WCIF** (download it from WCA Live, or from `https://www.worldcubeassociation.org/api/v0/competitions/<id>/wcif/public`): `{ formatVersion, id, name, shortName, persons, events, schedule }`.

- `persons`: `{ registrantId, name, wcaId, assignments: [{ activityId, assignmentCode }], … }`.
- `events`: `{ id: "333", rounds: [{ id: "333-r1", format: "a", results: [{ personId, attempts: [{ value }], best, average }] }] }` (WCIF 1 writes `{ result }` instead of `{ value }`). Attempts become solves like WCA results (table above), and `format` with the number of attempts gives the round's average (`roundMode`).
- `schedule`: `{ startDate, venues: [{ rooms: [{ activities: [{ id, activityCode: "333-r1", startTime, childActivities: [{ activityCode: "333-r1-g1", … }] }] }] }] }`, which gives the dates.

**CubeDesk's file** ("Export data", JSON): `{ sessions: [{ id, name, order }], solves: [{ session_id, event_type, time, raw_time, dnf, plus_two, scramble, started_at, ended_at, … }] }`. A solve's `time` is seconds with the +2 added (-1 for a DNF), and `raw_time` the seconds without it, so `time` is `raw_time` cut to hundredths (`toHundredths`), `penalty` is `"DNF"`, `2` or `null`, and `createdAt` is `ended_at` (ms). `doneAt` is "CubeDesk".

**Twisty Timer's backup** (`Backup_<date>.txt`): a header line with commas, then one solve per line with `;` and every field in quotes: `"333";"Normal";"12345";"1700000000000";"R U …";"0";"comment"` (puzzle, category, time in ms, date in ms, scramble, penalty, comment). Penalty `1` is a +2 that's already in the time (Twisty Timer adds 2000 ms), so `time` is the ms minus 2000; `2` is a DNF. `doneAt` is "Twisty Timer".

**csTimer's CSV** (from a session's stats, `csTimerExport_<date>.csv`): `No.;Time;Comment;Scramble;Date;P.1…`, `;` between fields, a field in quotes only when it holds a `;` or a newline. Time is written like "12.34", "DNF(12.34)" or "14.34+", and Date like "2026-10-31 14:07:09" (local time). Its solves' `doneAt` is "csTimer", like csTimer's file.

### `offline/`

The app works offline through a **service worker**: a script the browser keeps running in the background for the site, which sits between the page and the network and can answer the page's requests from a local cache. Pro Timer's is generated by vite-plugin-pwa (see [Build config](#build-config-viteconfigjs)); there's no hand-written service worker code.

How it works, from build to an offline visit:

1. **Build:** `npm run build` writes `dist/sw.js` with a precache list of all 18 files the app needs (the page, the JS and CSS bundles, the small `workbox-window` bundle `registerSW` loads, csTimer's scrambler and the 13 sounds), each with a revision hash of its contents.
2. **First visit (online):** `offline/offlineController.js` registers `sw.js`. The service worker downloads every file on the list into a cache (`workbox-precache-v2-…`) and takes over the next page loads.
3. **Later visits, online or offline:** every request goes through the service worker, which answers from the cache. Opening the page itself (`/Pro-timer/` or any path under it) gets the cached `index.html`. Solves and settings don't need it: they're in localStorage, which is on the device anyway.
4. **New version:** on a later visit online, the browser sees that `sw.js` changed (new revision hashes after a deploy), downloads only the files that changed, and leaves the new service worker **waiting**, so the open page keeps running the old version. The plugin then calls `onNeedRefresh`, which shows the bar.
   - **Reload** calls `updateSW()`: the waiting service worker takes over and the page reloads into the new version. As it takes over, it deletes the cached files that are no longer on its list.
   - **Later** only hides the bar. The new version starts by itself once every tab of the app is closed and it's opened again.

- **`offlineController.js`**: imports `registerSW` from `virtual:pwa-register` (a module the plugin makes; in `npm run dev` it does nothing). `registerSW({ onNeedRefresh })` registers the service worker and returns `updateSW`. `onNeedRefresh` adds `.open` to `#updateBanner`; the Reload button calls `updateSW()`, and Later removes `.open`. It also calls `navigator.storage.persist()`, which asks the browser not to clear the site's storage (the saved solves and the cached app) when the device runs low on space.
- **`updateBanner.html`** and **`offline.css`**: the bar, fixed at the bottom of the page, hidden until `.open`.

### `cubisz/` and `public/`

The app only uses cubisz through `cubisz/api.js`: `mountCube(element)`, `setSize`, `setView("3d")`, `setFMC(true)`, `applyScramble(scramble, skipPaint)`, `applySolution(moves, skipPaint)` (both repaint the cube unless `skipPaint` is true), `getLastMoveCount()` and `checkSolved()`. `public/cstimer_module.js` is csTimer's scrambler, answering the worker messages `scramble`, `image`, `seed` and `set`.
