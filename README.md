# Pro Timer

A speedcubing timer for competition-style practice, without setup or bookkeeping by hand.

Its average system started as a bug: averages of 5 came out in fixed blocks of five solves instead of rolling over the last five. That turned out to feel like a competition round, so it became the timer's main idea.

**Try it:** https://cubing-way.github.io/Pro-timer/

## Features

- **Events and scrambles:** every WCA event plus csTimer's training sets (PLL, OLL, ZBLL, COLL, last layer, edges or corners only…), generated by csTimer's scrambler in a worker, with a picture of the scrambled cube drawn by [cubisz](https://github.com/Cubing-Way/cubisz). Previous and Next in the top bar go back through the scrambles you've seen or skip to a new one, in every event.
- **Block averages:** ao5, mo3, bo3, bo5 and ao3 (for FMC) are counted in blocks, like competition rounds. *Classic* keeps the usual rolling averages.
- **Sessions:** separate sessions with their solve history, +2 and DNF penalties, and the details of every solve and average, including the one in progress.
- **Statistics:** per session, over all time, the year, the semester, the month or the week.
- **Timer:** WCA inspection and delay flag, timer phases, typed-in times, hide the time while solving, and timer warnings for long attempts (such as a 1-hour limit).
- **Fewest Moves:** write your solution, test it on the cube and submit it; cubisz checks it and counts the moves.
- **Multi-Blind:** pick how many cubes and get a scramble for each.
- **TPS:** turns per second for a solve once its move count is known.
- **Look:** colors for the text, backgrounds and buttons, and switches for the scramble picture, statistics, session history, scramble text, penalty bar and average preview.
- **Saving:** sessions and settings stay in your browser.
- **Offline:** after the first visit, the app works without internet. When a new version is out, a bar asks before switching to it, so it never reloads in the middle of a solve.

## Run it

```bash
npm install
npm run dev
```

Then open http://localhost:3000/Pro-timer/.

## Build and deploy

```bash
npm run build
```

The site lands in `dist/`. `npm run deploy` builds it and publishes `dist/` to the `gh-pages` branch, which GitHub Pages serves.

## Test offline

The service worker only exists in the build (`npm run dev` doesn't register one), so test offline mode on a built copy:

```bash
npm run preview
```

It builds, then serves `dist/` at http://localhost:4173/Pro-timer/. Open it once, then in DevTools tick **Offline** in the Network tab (or stop the server) and reload. DevTools → Application → Service workers and Cache storage show what's registered and cached. To start over, click **Unregister** there and delete the `workbox-precache-…` cache.

## Folder layout

- `index.html`: the page skeleton; each part of the page lives in its own folder
- `vite.config.js`: Vite settings, the plugin that puts the page's HTML pieces together, and the offline plugin
- `main/`: entry point, the bridge to csTimer's scrambler, page-wide styles
- `timer/`: the timer, inspection, WCA delay, phases, countdown and time formatting
- `average/`: block and classic averages
- `session/`: sessions and solves
- `scramble/`: scramble types, generation and the scramble picture
- `cubisz/`: the cubisz cube, used for scramble pictures and Fewest Moves checks (a copy of its own repo, with a demo page and its own `style.css`)
- `event/`: Fewest Moves, Multi-Blind and the timer warnings
- `render/`: history list, statistics and average views
- `stats/`: the statistics page and its charts
- `settings/`, `topbar/`, `modal/`, `timeTyping/`: settings, top bar, pop-ups and typed-in times
- `offline/`: registers the service worker that makes the app work offline, and the bar that offers new versions
- `public/`: files served as they are: csTimer's scrambler worker (`cstimer_module.js`) and the timer warning sounds (`audio/`)

Each folder has a `…Controller.js`. It holds the folder's state and page wiring (listeners, startup code), and it is what other folders import. The other files only export functions: when one needs state, its controller passes it in. State shared between folders lives in `…State.js` files (`avgState.js`, `sessionState.js`, `settingsState.js`, `timerState.js`, `topbarState.js`). `main/mainController.js` loads the controllers, then shows the first scramble.

A folder also holds the HTML and CSS of the part of the page its controller wires up, so the markup, the styles and the code for one feature sit side by side.

## The page (HTML)

`index.html` is only a skeleton. Each part of the page is in its own `.html` file, and the skeleton pulls it in with a tag like this:

```html
<include src="./topbar/topbar.html"></include>
```

`<include>` is not real HTML. The `htmlIncludes` plugin in `vite.config.js` replaces every `<include>` tag with the contents of that file before the browser sees the page, both in `npm run dev` and in `npm run build`, so the browser only ever gets one complete page, the same as if it were written in one file. How it works:

- `expandIncludes(html, fromDir)` finds each `<include src="…"></include>` with a regular expression (`INCLUDE_TAG`), reads that file and puts its contents in place of the tag.
- It runs again on the file it just read, so a piece can include smaller pieces. The path in `src` is relative to the file that has the tag, like an `import`.
- The plugin's `transformIndexHtml` hook runs it on `index.html` with `order: "pre"`, before Vite's own HTML handling, so Vite still processes the `<link>` and `<script>` tags as usual.
- Vite doesn't track the pieces as modules, so its `handleHotUpdate` hook reloads the page whenever any `.html` file changes in dev.

Because the whole page is there before any script runs, the controllers can still look up their elements with `document.getElementById` when they load.

## Styles (CSS)

`index.html` links a single stylesheet, `main/style.css`. That file has no rules of its own: it `@import`s every other stylesheet, and Vite inlines them into one file (in dev and in the build). The import order matters, because when two rules match the same element equally strongly, the one imported later wins. Each phone rule sits at the end of its own file in a `@media (max-width: 768px)` block, after the desktop rules it overrides.

| `scramble/scramble.css` | Scramble text and the desktop and phone scramble pictures |

How the colors work: every color in the stylesheets is a CSS variable (`--bg-main`, `--bg-secondary`, `--bg-tertiary`, `--text-main`, `--text-strong`, `--border-main`, `--accent`…), with defaults in `main/variables.css`. The theme classes are tables of values for those variables. When you pick a background color in the settings, `settings/settingsController.js` (`getThemeVar`) adds a hidden element with that theme's class, reads one variable from it, and sets it on `<html>`, which overrides the default for the whole page. The "Secondary text" color puts a `.theme-text-<color>` class on `<body>` instead, and "Main text" sets `--times-color`, which only `.times-color-number` (times and numbers) uses. Each color setting changes one variable:

| Setting | Variable | Used by |
| --- | --- | --- |
| Main text | `--times-color` | Times and numbers |
| Secondary text | `--text-main` (via a class on `<body>`) | All other text |
| Main background | `--bg-main` | Page, right sidebar, penalty bar, footer, stats page, settings panel |
| Secondary background | `--bg-tertiary` | Top bar, left sidebar, settings rows |
| Tertiary background | `--bg-secondary` | Pop-ups, stats table header |
| Buttons background | `--border-main` | Buttons, selects, inputs and most borders |

Some elements are hidden in the CSS and shown by the code: the event buttons and Fewest Moves panel (`event/eventLayout.js`, `event/FMC.js`, `event/MBLD.js` set their `display`), and the pop-ups (opened by adding `.open`, removing `.hidden`, or setting `display`). The Layout settings hide parts of the page by class (`settings/layout.js`).

## Build config (`vite.config.js`)

- `base: "/Pro-timer/"`: the site is served from `cubing-way.github.io/Pro-timer/`, so every URL starts with `/Pro-timer/`.
- `server.port: 3000`: the dev server address.
- `worker.format: "es"`: web workers are built as ES modules.
- `build.minify: false`: the built code stays readable.
- `plugins`:
  - `htmlIncludes()`: puts the HTML pieces together (see [The page](#the-page-html)).
  - `VitePWA({...})` from [vite-plugin-pwa](https://vite-pwa-org.netlify.app/): writes the service worker (`dist/sw.js`, plus the Workbox library it uses) at build time (see [Offline](#offline)). Its options:
    - `registerType: "prompt"`: a new version waits until the user clicks Reload, instead of reloading the page on its own.
    - `injectRegister: false`: the plugin adds no registration script; `offline/offlineController.js` registers the service worker.
    - `manifest: false`: no web app manifest yet (it needs app icons), so the app works offline but can't be installed.
    - `workbox.globPatterns`: which files in `dist/` go in the precache list: `js`, `css`, `html` and `mp3`.
    - `workbox.ignoreURLParametersMatching`: `main/cstimer.js` loads the scrambler as `cstimer_module.js?worker_file&type=classic`; ignoring `worker_file` and `type` lets that request find the cached `cstimer_module.js`.

## Code

Plain JavaScript modules, no framework. Each folder's controller runs its setup code (listeners, saved settings, first draw) the first time it's imported. Folders share state through the `…State.js` objects, and functions that need state get it passed in by their controller.

### Startup

1. `index.html` links `main/style.css`, then loads `main/mainController.js` as a module.
2. `mainController.js` imports every controller. A module's code runs once, after the modules it imports, so things happen in dependency order:
   - `session/sessionState.js` reads all sessions from localStorage, and `session/sessionController.js` loads the current one's average in progress (`changedSession`) and fills the session select.
   - `settings/settingsController.js` applies the saved colors, layout switches and timer settings.
   - `event/eventController.js` picks where scramble pictures go (`vis`: the desktop corner, or the phone pop-up when the window is 768px wide or less) and shows the timer or the typing box.
   - `topbar/topbarController.js` fills the category select, sets the category, event and mode selects to the session's (running their change handlers), wires the penalty buttons and draws the history (`renderHistory`).
   - `offline/offlineController.js` registers the service worker (in the build only) and asks the browser to keep the saved data.
3. Last, `mainController.js` awaits `initEvent()`, which shows the first scramble and, for Fewest Moves or Multi-Blind, their layout.

### The path of one solve

1. **Press** (space down, or a finger on `#touchOverlay`): `onPressStart` in `timer/timerController.js`. From idle it starts inspection (or waits for the release, with "Press end"); during inspection it starts the hold.
2. **Hold**: `beginHold` (`timer/timerPhases.js`) turns the timer red, and green after 0.3 s (right away with the delay flag off).
3. **Release** while green: `onPressEnd` starts the timer (`startTimer`, `timer/timer.js`) and hides everything but the timer (`showOnlyTimerSafe`).
4. **Press while running** (any key but Tab): `handleSplitOrStop` ends the current timer phase. On the last phase it stops the timer and reads the final time from the display.
5. `averageOfN` (`average/avgController.js`) works out the inspection penalty and adds the solve to `averageObj.solvesArray`. In classic mode it updates the rolling averages; otherwise, once there are enough solves for the mode, it returns a finished average block.
6. `addAverageBlock` (`session/`) puts the block at the start of `session.averages`, and `saveSessions` writes everything to localStorage.
7. `renderHistory` (`render/renderController.js`) redraws the footer, the history list and both stats panels.
8. `displayScramble` (`scramble/scrambleController.js`) asks csTimer's worker for the next scramble and its picture and adds it at the end of the scramble history (so a solve done on an older scramble, after Previous, still gets a new one), and `restoreUI` shows the page again.

Typed-in times (`timeTyping/`), Fewest Moves and Multi-Blind (`event/eventController.js`) skip the timer and call `averageOfN` from step 5 with the typed time, the move count or the points.

### Data

A **solve**, as saved in `averageObj.solvesArray` and in average blocks:

| Field | Meaning |
| --- | --- |
| `time` | Seconds; the move count for Fewest Moves, the points for Multi-Blind |
| `penalty` | `null`, a number of seconds added (2, 4 … 12), or `"DNF"` |
| `result` | Multi-Blind only: `"4 / 5"` |
| `scramble`, `event` | The scramble and the event code it was made for |
| `inspection` | Seconds of inspection used (0 for typed times, FMC and Multi-Blind) |
| `createdAt` | When it was saved (ms since 1970), used by the date filters and to find the most recent solve |
| `solution` | Fewest Moves solution, or one typed in the details pop-up |
| `solvePhases` | Time of each timer phase |
| `moves`, `tps`, `status` | Set when a solution is checked in the details pop-up |

An **average block** (one finished average): `mode`, `average`, `best`, `worst`, `sigma` (already formatted as text, like `"12.34"` or `"DNF"`) and `solves`.

A **session** (in `sessionsObj.sessions`, by name): `averages` (finished blocks, newest first), `buffer` (the average in progress: `mode`, `solveCounter`, `solvesArray`), `classicStats` (classic mode's rolling averages), and the `category`, `scrambleType` (event) and `mode` it was last used with.

**localStorage keys**: `sessions` and `currentSession`; the settings `main-background`, `secondary-background`, `tertiary-background`, `buttons-background`, `text-color`, `times-color`, `inspectionType`, `inspectionStart`, `delayFlagType`, `timerDisplay`, `timeInsertion`, `totalSolvePhases`; one `visibility-<select id>` per layout switch; and `timerWarningConfig_v1` for the timer warnings.

### `main/`

- **`mainController.js`**: the entry point. Imports every controller (including `offline/offlineController.js`), then `await initEvent()`.
- **`cstimer.js`**: runs csTimer's scrambler (`public/cstimer_module.js`) in a web worker, so making scrambles never freezes the page. `call(type, args)` sends `[id, type, args]` to the worker and keeps the promise's `resolve` in `callbacks[id]`; when the worker answers `[id, type, result]`, `onmessage` resolves that promise. It exports `csTimer` with `getScramble(type, length)`, `getImage(scramble, type)` (an SVG picture), `setSeed(seed)` and `setGlobal(key, value)`.

### `timer/`

- **`timerState.js`**: `PHASE` (the timer's phases) and `timerObj` (the current phase, interval and timeout ids, inspection time, timer phases of the solve in progress). `countdownObj` holds the 1-hour countdown for Fewest Moves and Multi-Blind.
- **`timerController.js`**: all keyboard and touch handling. What a press and a release do in each phase:

  | Phase | Press | Release |
  | --- | --- | --- |
  | idle | → inspecting (inspection starts now with "Press start"); with inspection off, straight to the hold | |
  | inspecting | `beginHold` → holding | starts inspection, with "Press end" |
  | holding | | `cancelHold` → back to inspecting or idle |
  | ready | | → running, `startTimer` |
  | running | `handleSplitOrStop` | |

  `onPressLost` cancels a hold when the release can't come (touch cancelled, tab hidden, window blurred). Escape cancels everything and puts the last solve back on the timer. Tab switches between Timer and Typing (`setTimeInsertion`). `setTimerDisplay(colorOrTime, content)` is the only function that writes on the timer; the other timer files get it passed in. `inspection2` is a separate seconds count used for inspection in Typing mode; when it stops (a press, or on its own at 17 s) the timer shows the last solve again.

  `showLastSolve()` writes the session's most recent solve on the timer: it gets the solve from `getLastSolve` (`session/`) and formats it with its penalty using `formatDisplayTime` ("14.34 (+2)", "DNF"), or shows "0.00" when the session has no solves. On Fewest Moves and Multi-Blind (`timerSettObj.untimedEvent`) it does nothing, because the timer shows their countdown there. If the last solve is a Fewest Moves or Multi-Blind result (moves or points, not a time), it shows "0.00". Escape, the end of `inspection2` and deleting a solve (`removeSolve` in `modal/`) all call it.
- **`timerPhases.js`**: `beginHold` (red, then green after `HOLD_DELAY_MS`), `cancelHold`, `resetTimerColor`.
- **`timer.js`**: `startTimer` updates the display every 10 ms from `performance.now()` (or shows "Solving" with "Hide while solving"); `stopTimer` writes the final time and goes back to idle.
- **`inspection.js`**: `inspection(type, setTimerDisplay, timerObj)` counts inspection and stores the exact time in `timerObj.inspection`; WCA inspection plays the 8 and 12 second calls and stops at 17.
- **`timeFormatting.js`**: `formatTime(ms)` for the running timer ("12.34", "1: 02.34", "1: 02: 03.45"), truncated like the WCA does.
- **`countdownTimer.js`**: `startTimer2` (start or stop the countdown, playing the ticked warnings from `public/audio/`), `stopTimer2` (reset to one hour), `updateDisplay`.

### `average/`

- **`avgState.js`**: `averageObj` (the mode and the solves of the average in progress) and `classicStats` (classic mode's `current`, `best` and `history` mo3, ao5, ao12 and ao100).
- **`avgController.js`**: `averageOfN(time, scramble, inspection, inspectionType, isFMC, modeFlag, isMBLD, solvePhases)`. It turns the input into a value (seconds, moves or points), applies the penalties (WCA inspection: 15 s is +2, 17 s is DNF; an unsolved FMC cube or 0 points or less is DNF), saves the solve, and returns a finished block when the mode has enough solves (`getNeededSolves`), removing those solves from the buffer. With `modeFlag` it adds no solve and only re-checks the buffer after a mode change. It also re-exports the helpers below.
- **`avgComput.js`**: `computeAverage(solves, mode)` returns `{ dnf, avg, best, worst, sigma }`. A DNF counts as `Infinity`, so it sorts last.

  | Mode | Result | It's a DNF when |
  | --- | --- | --- |
  | ao5 | Drop best and worst, mean of the middle 3 (with 4 solves done it also gives the best and worst possible ao5) | 2 or more DNFs |
  | mo3 | Mean of 3 | any DNF |
  | bo3 | Best single; `avg` is the mean of the successful attempts | all 3 are DNF |
  | bo5 | Best single; `avg` is the ao5 of the same solves | all 5 are DNF (the best is then a DNF) |
  | fmc3 (ao3) | Mean of 3 move counts | 2 or more DNFs |
  | ao12, ao100 | Drop the best and worst 5% each, rounded up (1 for ao12, 5 for ao100), mean of the rest | more DNFs than that (2 for ao12, 6 for ao100) |

  For Multi-Blind, more points is better, so `bestAndWorst` flips the comparison.
- **`classicAvgs.js`**: `updateClassicStats(recomputeBest, averageObj, classicStats)`. After a new solve, it adds the rolling averages ending at that solve and updates the bests; with `recomputeBest` it rebuilds the whole history by sliding a window over every solve (after a penalty, a removed solve, a session change or switching to classic).
- **`avgHelper.js`**: `parseTimeToSeconds` ("1:02.50" → 62.5), `formatSecondsToTime` (62.5 → "1:02.50", Infinity → "DNF"), `formatDisplayTime` (a solve with its penalty: "14.34 (+2)"), `isPointsSolves` (true for Multi-Blind solves), `getNeededSolves(mode)` (how many solves finish a block: 5 for ao5 and bo5, 12 for ao12, 3 for mo3, bo3 and ao3).

### `session/`

- **`sessionState.js`**: `sessionsObj`: every session by name (from localStorage), the current session's name and the session select.
- **`sessionController.js`**: `getCurrentSession`, `saveSessions` (copies the average in progress into the session's `buffer`, then saves all sessions), `renderSessionSelect`, and the select's New, Rename and Delete actions. `switchSession` saves, changes session and fires a `sessionChanged` event, which the top bar answers by loading the new session (`changedSession` copies its buffer and classic stats into the shared state) and setting its selects. `clearAverages` empties the session after asking. The other functions pass the session state to `solve.js`.
- **`solve.js`**: `addAverageBlock`, `getSessionAverages`, `getLastSolveTarget` (the most recent solve: the last one of the average in progress or the last one of the newest saved average, whichever has the later `createdAt`; a solve saved without `createdAt` counts as 0, so the average in progress wins ties), `getLastSolve` (the solve object `getLastSolveTarget` points at, or `null`; the timer shows it), `penalty2` (change a solve's penalty; a saved solve's block is recomputed), `remove2` (remove a solve; a solve from a finished average either reopens that average or deletes it), `applyPenaltyToLast` and `removeLastSolve` (the buttons under the timer). In `penalty2` and `remove2`, a `blockIndex` of -1 means a solve of the average in progress (`averageObj.solvesArray`), and any other number is the index of a saved average in `session.averages`.

### `scramble/`

- **`scrData.js`**: `scrdata`, csTimer's list of scramble types by category: `[category, [[label, type, length], …]]`.
- **`scrambleController.js`**: the scramble on screen and the history behind Previous / Next.
  - `currentScramble` and `currentScrambleEvent`: the scramble on screen and its event code. They're exported `let`s, so every importer sees the new value after Previous or Next, and the next solve is saved with whatever is on screen.
  - `scrambleHistory`: every scramble shown for the current event, oldest first, as `{ scramble, event, svg }` (the SVG is kept so going back doesn't ask the worker again). `historyIndex` is the position of the one on screen. It keeps at most `MAX_HISTORY` (100) and forgets the oldest past that.
  - `displayScramble(event, vis, length)` gets a new scramble and its SVG picture from the worker (`length` overrides the default, for the Multi-Blind cube count). If the event changed, it empties the history first, since the old scrambles are for another puzzle. Then it adds the new one at the end, points `historyIndex` at it and shows it.
  - `showScramble(entry, vis)` puts a history entry on screen: sets `currentScramble` and `currentScrambleEvent`, draws the picture, sizes it with `adjustVisualizerSize` (a scale and position per puzzle), writes the text (Megaminx one row per line), greys out Previous on the oldest entry and fits the text (`autoFitText`).
  - `previousScramble(vis)` shows the entry before the current one (nothing on the oldest). `nextScramble(event, vis, length)` shows the entry after it, or calls `displayScramble` for a new one when already on the newest.
- **`scrHelpers.js`**: `getScrambleConfig(code)` (type and length from `scrdata`), `isCubiszEvent` (3x3 events, the only ones cubisz can check), `autoFitText` (shrinks the scramble text until it fits), `formatMegaminx`.
- **`scrVisualiser.js`**: `setVisualizerScale(scale, right, bottom, vis)` scales and places the desktop or phone picture.

### `event/`

- **`eventController.js`**: `eventObj.event` (the current event code) and `vis`. Fewest Moves: typing a solution applies it to the cube live, "Test solution" shows the move count and whether it solves the cube, "Submit solution" saves the move count as the result. Multi-Blind: `submitMBLD` turns "solved/total" into points and saves it; "View Scrambles" opens the list of scrambles for the chosen number of cubes. Timer warnings: `timerWarnings` (minutes left → on or off), saved in localStorage. Previous / Next scramble: the top bar buttons call `previousScramble` and `nextScramble`, only while `canChangeScramble()` (the timer is idle, so a scramble never changes during inspection or a solve). They work in every event: in Multi-Blind, Next makes scrambles for the number of cubes in the pop-up's box, and in Fewest Moves `resetFMCForScramble` puts the new scramble on the cube (`applyScramble`) and clears the old solution and result. `initEvent()` shows the first scramble.
- **`eventLayout.js`**: `showTimerLayout` (the layout of every timed event), `showTimeInsertion` (timer or typing box; Fewest Moves and Multi-Blind are untimed), `setEventInspection` (no inspection for blindfolded events).
- **`FMC.js`**: `handleFMC` switches to the Fewest Moves layout and mounts the cubisz cube with the scramble applied.
- **`MBLD.js`**: `handleMBLD` (Multi-Blind layout), `calculateMBLDPoints("4/5")` → `{ points: 3, result: "4 / 5" }` (throws on bad input), `parseMBLDScramble` (one scramble per cube), `renderMBLDGrid` (number, scramble and picture per cube).

### `render/`

- **`renderController.js`**: `renderHistory()`, called after every change. It decides what the footer shows (the average in progress if it has solves, else the newest saved one) and redraws the four areas below. `formatStatValue(value)` is the helper with the current session filled in.
- **`renderAvgBuffer.js`**: `renderCurrentAverage`, the footer's left panel (the current average's solves, or the current rolling averages in classic mode).
- **`renderBufferAvgStats.js`**: `renderAvgStats`, the footer's right panel (best, worst, σ; best and worst possible ao5 with 4 of 5 solves; the best rolling averages in classic mode).
- **`renderHistoryList.js`**: `renderHistoryList`, the left sidebar (past averages with their solves, or every solve in classic mode).
- **`statistics.js`**: `renderStats`, one right sidebar panel (best single, best average, mean, σ, solves).
- **`renderHelpers.js`**: `wrapTimesValue` (puts a value in the "Main text" color), `formatStatValue` (a solve or number as text: time with penalty and phases, moves, points, "DNF" or "-").

### `stats/`

- **`statsController.js`**: `getStatistics()` and `getStatisticsByDate(range)` (the sidebar's "All time" and "Today"), and `renderStatsPage()`, which fills the statistics page for the chosen period: the overview cards, four Chart.js charts (solve times; averages compared with the closest earlier period that has averages; σ per average; how many solves fall under each time) and the averages table (one row per average finished in the period, newest first, or one per solve of the period with its rolling averages in classic mode).
- **`statsHelpers.js`**: `getAllSolvesFromSession`, `getStatisticsFromSolves` (best single, mean, σ, best average, solve count), the date ranges (`getRangeTimestamps` for the current day, week, month, semester or year in local time; `filterSolvesByRange`, `filterAveragesByRange`, `getAveragesInRange`, `getLastRangeWithData`), and the chart data (`getSigmaGraphData`, `generateSmartThresholds`, `getTimeDistribution`, `getDistributionLabels`, `filterEmptyBuckets`, `buildAvgMaps`).

### `settings/`

- **`settingsController.js`**: opens and closes the panel, connects the Layout switches (`bindVisibilityToggle`), and loads, applies and saves every setting. Colors use `getThemeVar` (see [Styles](#styles-css)); if a text color has the same base color as its background (red text on a red background), it switches to black or white instead. `setTimeInsertion` switches Timer / Typing and `updateTypingUI` shows or hides the typing box. `delayFlagType` and `timeInsertion` are exported, so the other folders always read the current value.
- **`settingsState.js`**: `timerSettObj`: `inspectionType`, `timerFlag` (true when the timer is off) and `untimedEvent` (Fewest Moves or Multi-Blind).
- **`layout.js`**: `bindVisibilityToggle(selectId, targetClass)` shows or hides every element with a class from a Display / None select, and remembers the choice.

### `topbar/`

- **`topbarController.js`**: fills the category select from `scrdata` and the event select from the chosen category. Changing the event saves it in the session, sets the layout, the inspection type and the WCA average mode for it (`getDefaultModeForEvent`: bo5 for 3BLD, bo3 for 4BLD, 5BLD and Multi-Blind, mo3 for 6x6 and 7x7, ao3 for FMC, ao5 otherwise), stops a running countdown and shows a new scramble. Changing the mode saves it and re-checks the average in progress. It also handles the `sessionChanged` event, the Clear, Open Session and penalty buttons (+2 steps through +2 … +12), the phone scramble button, and takes the focus off clicked buttons and selects so the space bar keeps driving the timer.
- **`topbarState.js`**: `plus2CounterObj`, the +2 button's current step.

### `modal/`

- **`modalController.js`**: `openDetailsModal()` builds the pop-up (the Open Session button). The first card is the average in progress, if it has solves. Its header shows how many solves are done out of how many the mode needs ("ao5 in progress: 3/5"), plus bpAo5 and wpAo5 when an ao5 has one solve left. In classic mode it lists every solve instead, since they all stay in the buffer. Then come the saved averages, newest first. Every solve row is built by `solveRowHtml(solve, index, blockIndex)`: time, penalty buttons, scramble, inspection, date and, for 3x3, a solution box. Its buttons carry `data-block` and `data-solve`, and a `data-block` of -1 marks a solve of the average in progress. `setPenalty` and `removeSolve` change a solve, recount the classic rolling averages, save, redraw and rebuild the pop-up. `removeSolve` also puts the new last solve on the timer (`showLastSolve` from `timer/`); the X button under the timer goes through it too. `submitSolution` checks a typed solution on cubisz and saves its move count, TPS and status on the solve, in the buffer or in its saved average.

### `timeTyping/`

- **`timeTypingController.js`**: the Add button and the Enter key save a typed time. `normalizeTypedTime` accepts "12.34", "1:02.50" or digits only ("1234" → 12.34, "10234" → 1:02.34); anything else flashes the box red.

### `offline/`

The app works offline through a **service worker**: a script the browser keeps running in the background for the site, which sits between the page and the network and can answer the page's requests from a local cache. Pro Timer's is generated by vite-plugin-pwa (see [Build config](#build-config-viteconfigjs)); there's no hand-written service worker code.

How it works, from build to an offline visit:

1. **Build:** `npm run build` writes `dist/sw.js` with a precache list of all 18 files the app needs (the page, the JS and CSS bundles, the small `workbox-window` bundle `registerSW` loads, csTimer's scrambler and the 13 sounds), each with a revision hash of its contents.
2. **First visit (online):** `offline/offlineController.js` registers `sw.js`. The service worker downloads every file on the list into a cache (`workbox-precache-v2-…`) and takes over the next page loads.
3. **Later visits, online or offline:** every request goes through the service worker, which answers from the cache. Opening the page itself (`/Pro-timer/` or any path under it) gets the cached `index.html`. Solves and settings don't need it: they're in localStorage, which is on the device anyway.
4. **New version:** on a later visit online, the browser sees that `sw.js` changed (new revision hashes after a deploy), downloads only the files that changed, and leaves the new service worker **waiting**, so the open page keeps running the old version. The plugin then calls `onNeedRefresh`, which shows the bar.
   - **Reload** calls `updateSW()`: the waiting service worker takes over and the page reloads into the new version. As it takes over, it deletes the cached files that are no longer on its list.
   - **Later** only hides the bar. The new version starts by itself once every tab of the app is closed and it's opened again.

- **`offlineController.js`**: imports `registerSW` from `virtual:pwa-register` (a module the plugin makes; in `npm run dev` it does nothing). `registerSW({ onNeedRefresh })` registers the service worker and returns `updateSW`. `onNeedRefresh` adds `.open` to `#updateBanner`; the Reload button calls `updateSW()`, and Later removes `.open`. It also calls `navigator.storage.persist()`, which asks the browser not to clear the site's storage (the saved solves and the cached app) when the device runs low on space.
- **`updateBanner.html`** and **`offline.css`**: the bar, fixed at the bottom of the page, hidden until `.open`.

### `cubisz/` and `public/`

The app only uses cubisz through `cubisz/api.js`: `mountCube(element)`, `setSize`, `setView("3d")`, `setFMC(true)`, `applyScramble(scramble, skipPaint)`, `applySolution(moves, skipPaint)` (both repaint the cube unless `skipPaint` is true), `getLastMoveCount()` and `checkSolved()`. `public/cstimer_module.js` is csTimer's scrambler, answering the worker messages `scramble`, `image`, `seed` and `set`.
